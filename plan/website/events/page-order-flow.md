> **Renamed from `page-seat-picker.md` (2026-08-18 shaping).** The session merged the
> separate seats/checkout pages into **one continuous order flow** and discovered that the
> page's core question — how the club assigns seats — is an **undecided club fact**
> (`CONTEXT.md` → flagged ambiguities → seat allocation). This plan therefore ships the
> flow's **shell and frame** with a recognisable placeholder core, deliberately against the
> end-state rule (user ruling: undecided components become placeholders, everything else is
> built final).

## What & Why

One guided flow from "Karten wählen →" to the digital ticket — not a chain of separate
pages. The user clicks the direct buy CTA on the detail page (or the event
list), enters the flow, and is walked through "Kartenwahl" → "Deine Daten" → "Zahlung" with a
**persistent bottom CTA bar** carrying the important information (step, sum, primary
action) at every moment. The flow ends by redirecting to the mail-linkable confirmation.

The mock's signature interaction (the seating plan) may or may not survive — the club has not
decided between numbered seats and general admission. Until it does, step 1's core is a
designed, recognisably-placeholder panel; the frame around it states only both-worlds-true
facts.

## Decisions (shaping session, 2026-08-18)

1. **Seat allocation is undecided club practice** — numbered seats vs. general admission
   is *the* blocked decision of this page (`CONTEXT.md` flagged ambiguity). Building either
   variant would encode the decision, so step 1's core is a **recognisable placeholder**;
   this is the sanctioned exception to the end-state rule.
2. **One continuous flow, one route.** `/events/$eventSlug/order` carries the whole wizard;
   the current step lives in a **search param** (`?step=1|2|3`) so the browser back button
   steps back. The separately-pinned `/events/$eventSlug/seats` is **retired** (route file
   deleted, links re-pointed); a separate `/checkout` page is never built.
3. **Flow shell**: stepper ("Kartenwahl" · "Deine Daten" · "Zahlung") + the persistent bottom CTA
   bar as the flow's single navigation. Steps 2 and 3 are recognisable placeholders until
   `page-purchase` shapes them; step 3's placeholder action navigates to `/orders/demo` so
   the whole chain is walkable ("create all the pages… navigate through the UI", user).
4. **Confirmation is a capability URL**: `/orders/$orderCode`, where `orderCode` is an
   unguessable random token generated by the backend and sent only in the buyer's mail —
   never a guessable number (user challenge resolved: enumeration is the threat, entropy is
   the answer; a leaked URL equals a forwarded mail). Placeholder page now.
5. **Ticket language, not seat language** (glossary: Karte = entitlement, Platz = seat):
   step/kicker **"KARTENWAHL"**, entry CTA **"Karten wählen →"**; the shipped "Platz
   wählen →" / "Platzwahl" surfaces are renamed. Route identifiers stay English.
6. **State guard in the frame**: the flow renders in every `salesStatus`; non-purchasable
   states replace the core with a short notice + the right exit (presale states → presale date
   + back to detail, `soldOut` → "Zur Kartenbörse →", `cancelled`/`salesClosed` → back).
   Deep links land honestly, nothing redirects silently.
7. **Step-1 frame anatomy** (adopted, both-worlds-true, all derivable from the E1 seed):
   back link "← {title}" · kicker `KARTENWAHL · SA., 23. JANUAR · 19:11 UHR · DORFGEMEINDEHAUS`
   · state H1 ("KARTEN FÜR DIESEN ABEND." / `almostSoldOut`: "DIE LETZTEN N KARTEN.") ·
   stat line "14 € pro Karte · 18 von 260 frei" with the shared capacity bar · placeholder
   core panel ("HIER WÄHLST DU DEINE KARTEN — wie genau, fester Platz oder freie Wahl,
   entscheidet der Verein noch…") · bottom bar with "Weiter zum Kauf →". Saying *that* the
   mechanics are undecided is allowed; claiming either mechanic is not.
8. **Entry points**: the detail page's ticket panel + mobile sticky bar (existing, renamed)
   and a **direct flow CTA on the event list** for purchasable states (user:
   "detail page / or overview page → direct book button").
9. **Buyer accounts: extend Account** (user decision over the raised registry concern).
   Self-registration creates a real Person + Account with **no Membership**, so buyers
   can keep mail, ticket overview, history and payment methods; member onboarding stays
   invite-only via invitation. The duplicate-Person question is **flagged open** in
   `CONTEXT.md`. **No account UI is part of E4** — the account area is planned later as its
   own work; step 2's optional-login offer lands with `page-purchase` shaping.

## Blocked — waiting on the club

The seat allocation decision unblocks step 1's real core. Only *after* it, these become
shapeable (all embargoed until then, none may appear on any surface):

- Seating-plan geometry / real hall layout (if numbered seats) — per-event data, never baked
- Selection cap (mock: 10 — unverified), hold timer & what a hold means
- Location hints ("Nah an der Bühne"), group order, in-plan ticket-exchange returns
- Standing places (mock: 62 — invented), wheelchair-space handling (mock's "kurz anrufen" — no
  confirmed practice, no phone number allowed)
- Seat-grid accessibility (keyboard nav, SR seat naming, touch targets ≥ 44px — the mock's
  9px mobile seats are rejected regardless)

## Implementation plan (E4)

Three slices, per-slice review + full gates:

1. **S1 — Routes & rename sweep**: delete the `/events/$eventSlug/seats` route, create
   `/events/$eventSlug/order` (step search-param validation) and `/orders/$orderCode`
   (PlaceholderPage, extended for a custom CTA back to `/events`); ticket-language sweep
   (Platzwahl → Kartenwahl, "Platz wählen →" → "Karten wählen →", SEO titles, ticket-panel
   + sticky-bar targets → flow); list hero card gains the direct flow CTA.
2. **S2 — Flow shell**: stepper + persistent bottom CTA bar (one component, the flow's
   single navigation), step 2/3 recognisable placeholder bodies, step 3 → `/orders/demo`
   chain, browser-back = step-back behaviour.
3. **S3 — Step 1 frame**: state guard + notices, kicker/H1 ladder/stat line with the shared
   capacity bar, placeholder core panel; tests for the guard and display derivations;
   assembly + as-built notes.

## As-built (E4, 2026-08-18)

Built as the three planned slices; final gates green (typecheck, **911 tests** — 14 ui + 897
website —, lint, build). The plan held; the decisions and deviations worth carrying forward:

- **The flow is a page orchestrator, not a compound kit.** `EventOrderFlowPage` is a plain
  `FC<Props>` with parts under `internal/{layout,ui,logic}` — the shipped page idiom
  (`EventDetailPage`, `EventListPage`, `AlbumPage`). `Object.assign` stays reserved for
  reusable multi-slot kits (`PageLayout`, `KkHeroSection`, `ApplyForm`). No flow context: the
  3+-shared-consumer bar is not met, `useOrderFlowStep` is the single logic part.
- **The flow lives in the `events` feature**, not a feature of its own — it needs `Event`,
  `CapacityBar`, `TicketCtaButton` and the `deriveTicketPanelFace` ladder, and features never
  import from other features.
- **The blocked states hide the stepper *and* the bottom bar.** A persistent "Weiter zum Kauf →"
  under a sold-out notice would be dishonest; the exit CTA lives with the notice instead. The
  kicker's lead falls back from the step label to `KARTEN` in those states, so it never claims
  a "Kartenwahl" that cannot happen.
- **The state sentence has one home.** `deriveOrderFlowNotice` reuses `deriveTicketPanelNote`
  and appends a flow-owned suffix; `soldOut`'s suffix literally *is* `exchangeBandContent.note`,
  so no German is duplicated between the panel, the band and the flow.
- **`EventStickyBar` was promoted to `StickyActionBar`** (feature level, `sx`-driven, marker
  `data-kk-sticky-action-bar`) and is now shared by the detail page's mobile CTA and the flow's
  persistent bar. The detail page re-supplies `display: { desktop: 'none' }` +
  `justifyContent: 'space-between'` at its call site — its shipped behaviour is unchanged.
- **The bar stacks on phones.** Two `size="large"` buttons plus the step summary do not fit
  360px in one row, so the action row claims its own line below `sm`; one exported
  `STICKY_ACTION_BAR_STACKED_HEIGHT` feeds both the spacer and the bar's `minHeight`, so they
  cannot drift apart.
- **`?step=1` is never written to the URL.** `buildOrderFlowStepParam` maps step 1 to
  `undefined`, so the flow's entry URL stays clean and a garbage `?step` silently resolves to
  step 1 (`z.coerce…optional().catch(undefined)`) — no crash, no redirect, matching the
  gallery's `?photo` precedent.
- **Back is history-first**: `useCanGoBack` → `router.history.back()` when there is an entry to
  pop (so the browser button and the in-page "← Zurück" agree), and a `replace` navigation to
  the previous step when the user deep-linked straight onto step 2 or 3.
- **The stepper's numerals were a contrast failure** and were fixed during review: inactive
  circles now sit at 5.06:1 (light) / 6.02:1 (dark), active at 4.76:1 / 4.83:1 — dark-mode
  active was 3.52:1 before.
- **`BackLink`'s `to` widened to `LinkProps['to'] | string`** — the same trade-off E3 recorded
  for `SectionActionLink` and `BandCta`, and P4 for `buildPostHref`. The type-preserving route
  (`params={{ eventSlug }}`) was tried twice and rejected: MUI's `Link component={RouterLink}`
  drops `component` from its props type as soon as `params` is present (TS2769). Cost: the four
  literal call sites lose union checking on `to`.
- **`BlockedFaceKind` lives in `ticket-panel-display.ts`**, beside the `TicketPanelFace` it is
  derived from; `order-flow-content.ts` imports it with `import type`, so the cycle is erased at
  compile time.
- **An honesty guard ships as a test**: `order-flow-content.test.ts` ranges over every flow copy
  constant and fails on "Platzwahl" / "Platz wählen", so the ticket language cannot regress.
- **`CapacityBar`'s `aria-label` became "Vergebene Karten"** — the last Platz-for-entitlement
  string on a shipped surface.
- **No `robots: noindex`** on `/events/$eventSlug/order` or `/orders/$orderCode` (no route in
  the repo sets one, and the site sits behind the preview gate). Revisit with `page-purchase`,
  where a real confirmation URL makes the question sharper.
- **Outstanding**: no headless-browser pass was run for this phase (E3 set that precedent) —
  the bar's stacking and the stepper contrast were verified by measurement, not by screenshot.
